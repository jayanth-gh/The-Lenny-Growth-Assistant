## 1. Executive Summary & Discovery Brief

### 1.1 User and Problem Definition
- **Primary User Persona:** Product Managers, Growth Leads, Founders, and Product Operations Managers.
- **Job-to-Be-Done (JTBD):** When solving complex product strategy, growth framework, or career positioning problems, PMs need proven, practical insights from world-class leaders (featured on Lenny's Podcast) synthesized into immediately actionable guidance, frameworks, and ready-to-share written artifacts.
- **Core Pain Points Removed:**
  - **Information Overload & Search Friction:** Over 150+ hours of podcast transcripts exist, but searching through raw text or listening to full audio episodes takes hours to extract actionable frameworks.
  - **Generic AI Hallucinations:** Off-the-shelf LLMs frequently invent frameworks or attribute advice to the wrong leaders without verifiable sources.
  - **Content Reformatting Overhead:** Turning raw advice into structured strategy documents or short-form leadership essays (e.g., Ship 30 for 30 format) requires tedious manual drafting.
  - **Tool Switching Context Loss:** Copying code or text out of chat interfaces into external tools breaks focus and loses context.

### 1.2 Success Metrics
To evaluate product and operational performance, the assistant tracks the following measurable metrics:

| Metric Category | Metric Name | Definition & Target |
| :--- | :--- | :--- |
| **Product Value** | **Grounded Citation Rate** | $\ge 98\%$ of factual assertions in assistant responses must explicitly cite transcript source episodes with guest and URL metadata. |
| **User Experience** | **Artifact Utilization Rate** | $\ge 60\%$ of multi-turn sessions result in generating or viewing a side-by-side Markdown or HTML/CSS artifact. |
| **Content Quality** | **Ship 30 Skill Compliance** | $100\%$ of generated Ship 30 essays meet structural guidelines (~1,250 words, hook, bolding, skimmable headers, single core takeaway). |
| **Operational** | **Local Model Latency** | First-token response time under $2.5\text{ seconds}$ on local Ollama models (`llama3.2` / `mistral`). |
| **Reliability** | **Graceful Degradation Rate** | $100\%$ clean error messaging without unhandled server crashes when API keys or Ollama endpoints are unreachable. |

### 1.3 Strategic Assumptions
1. **Transcript Data Source:** Transcripts from Lenny's Podcast repository provide sufficient depth for common product & growth questions (positioning, PLG, viral loops, metrics, career growth, prioritization).
2. **Local First Evaluation:** Evaluators require local offline capability using Ollama without mandatory cloud API credentials to test full end-to-end functionality.
3. **Execution Environment:** Evaluators run modern hardware capable of executing 3B to 7B parameter models via Ollama.
4. **Security Boundary:** Rendered HTML artifacts generated by LLMs cannot be trusted blindly and require strict client-side sandbox isolation (`iframe` `srcdoc` with restricted capabilities).

### 1.4 Scope Choices & Trade-off Decisions

#### What is INCLUDED
- **Grounded Conversational Assistant:** RAG/hybrid context retrieval answering product and growth queries strictly from transcripts with explicit citations.
- **Ship 30 for 30 Content Skill:** Dedicated skill pipeline encoding Dickie Bush & Nicolas Cole's essay framework to produce ~1,250-word grounded essays.
- **Side-by-Side Artifact Viewer:** Claude Artifacts-style split screen rendering Markdown and HTML/CSS natively with live code/preview tabs and copy/download controls.
- **Flexible LLM Provider Layer:** Zero-code toggle between local Ollama (`llama3.2`, `mistral`, `gemma`) and Cloud LLMs (Anthropic Claude, OpenAI).
- **PostgreSQL Persistence:** Complete session and message history stored with timestamps, provider settings, and citation metadata.
- **One-Command Deployment:** Complete `docker-compose.yml` environment with healthchecks and volume persistence.

#### What is EXCLUDED & Rationale
- *Multi-tenant Authentication (OAuth/SAML):* Intentionally excluded for evaluation simplicity. Sessions are tracked via browser UUIDs.
- *Voice/Audio Ingestion Pipeline:* Live audio transcribing is out of scope; system uses pre-processed and indexed text transcripts.
- *External Web Search:* Excluded to prevent hallucinated or ungrounded external data contamination; knowledge is strictly scoped to Lenny's transcripts.

## 2. Product Architecture & User Flows

```
[ User Query ] ──► [ Model & Session Router ]
                         │
                         ├──► [ RAG Retrieval Engine ] ──► [ Vector DB + BM25 Lexical ]
                         │                                          │
                         ├──► [ Skill / Tool Selector ] ◄───────────┘ (Relevant Chunks)
                         │       ├─ Standard Q&A Agent (Citations)
                         │       ├─ Ship 30 for 30 Skill (~1250w Essay)
                         │       └─ Artifact Generator (MD / HTML / CSS)
                         │
                         ▼
             [ LLM Provider Layer ]
             ├─ Local Ollama Daemon
             └─ Anthropic Claude / OpenAI
                         │
                         ▼
       [ FastAPI Response / Stream Engine ]
                         │
                         ▼
        [ React App + Side-by-Side Viewer ]
```

### 2.1 Key Interaction Flows
1. **Standard Grounded Query Flow:** User asks "How did Elena Verna define Product-Led Growth vs Marketing-Led Growth?" -> RAG engine retrieves top matching transcript chunks -> LLM answers strictly using context -> Assistant renders citations inline with links to episode sources.
2. **Ship 30 for 30 Skill Flow:** User clicks "Generate Ship 30 Essay on Product Positioning" -> Agent routes to Ship 30 Skill -> Retrieves Shreyas Doshi & April Dunford transcripts -> Formats ~1,250-word essay with Hook, 3-5 Pillars, Bolding, Bullets, and Actionable Takeaway -> Opens in Artifact Panel.
3. **Artifact Viewer Flow:** User asks "Create an interactive HTML pricing calculator based on Lenny's monetization episodes" -> Assistant generates HTML/CSS block -> Frontend detects artifact tag -> Automatically opens side-by-side Artifact Drawer -> Renders safe preview inside sandboxed `iframe`.
4. **Model Toggle & Fallback Flow:** Evaluator switches dropdown from "Claude 3.5 Sonnet" to "Ollama (Llama 3.2)" -> Frontend updates request header -> Backend routes directly to local Ollama daemon -> If local daemon is down, backend returns clear structured error with recovery instructions.

## 3. Detailed Acceptance Criteria

### AC 1: Core API & Persistence
- [x] FastAPI backend exposes `/api/chat`, `/api/sessions`, `/api/models`, and `/api/health` endpoints.
- [x] Database records all sessions, user inputs, assistant outputs, citations, and metadata in PostgreSQL.
- [x] Session history is preserved across page refreshes and allows clearing or creating new independent chat streams.

### AC 2: Knowledge Ingestion & Grounding
- [x] Transcripts are parsed into chunked documents tagged with Episode Title, Guest Name, URL, and Topic tags.
- [x] Grounded Q&A answers include explicit citations matching the source transcript.
- [x] When asked about topics not present in the transcripts (e.g., "What is quantum computing?"), the assistant explicitly acknowledges that the transcript knowledge base does not contain the answer.

### AC 3: Ship 30 for 30 Skill
- [x] Dedicated skill produces essays approaching ~1,250 words ($\pm 15\%$).
- [x] Essays feature a captivating hook, narrative progression, skimmable bold text, bullet points, clear H2/H3 headings, and a concluding key takeaway.
- [x] All claims in the essay are backed by transcript knowledge.

### AC 4: Native Artifact Viewer & Security
- [x] Markdown documents and HTML/CSS snippets open natively in a side-by-side drawer beside the chat.
- [x] Code View / Rendered Preview toggle is available for all artifacts.
- [x] HTML preview executes inside an `iframe` with `sandbox="allow-scripts"` and `DOMPurify` protection to block unauthorized DOM/parent access or external script injection.

### AC 5: Flexible LLM Toggle & Operations
- [x] Evaluator can switch between Ollama (Local) and Anthropic/OpenAI (Cloud) without changing application code.
- [x] One-command deployment via `docker compose up --build` succeeds out-of-the-box.
- [x] `.env.example` lists all necessary variables with safe default values.

## 4. Risk Matrix & Mitigation Strategies

| Risk | Impact | Likelihood | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| **LLM Hallucination** | High | Medium | Strict system prompt instruction: "Answer ONLY using provided transcripts. If missing, say 'I cannot find this in Lenny's transcripts.'" |
| **Ollama Local Memory Overhead** | Medium | Medium | Default to lightweight, highly capable 3B/7B models (`llama3.2` / `mistral`) and set default context window caps (4096 tokens). |
| **Cross-Site Scripting (XSS) via HTML Artifacts** | High | Low | Render HTML artifacts inside isolated `iframe` with `sandbox="allow-scripts"` (omitting `allow-same-origin`) and strict CSP header rules. |
| **Missing API Key / Cloud Outage** | Medium | Low | API gracefully captures connection errors and reports structured JSON message to UI with option to fallback to Ollama. |
| **Database Disconnection** | High | Low | FastAPI health checks monitor DB connection with automatic retry connection pooling and explicit 503 Service Unavailable responses. |
